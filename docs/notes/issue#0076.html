Implementation Notes

Issue #76 — Add gitee pr review for approvals and review comments — 2026-07-10

Design Decisions

Decision Model review actions explicitly

Ambiguity: The command needed to share body handling while keeping approval and comment semantics distinct.

Choice: Added a PrReviewAction enum with approval and comment variants.

Rationale: The public request type prevents invalid mixed states from reaching the service and keeps future action-specific behavior localized.

Decision Reuse canonical write-target resolution

Ambiguity: Human-name remotes may resolve to a different canonical private repository.

Choice: Reused and renamed the existing PR write-target resolver for both comments and approvals.

Rationale: Review actions now match existing PR comment behavior without duplicating fallback logic.

Decision Preserve non-authentication 400 errors

Ambiguity: Gitee may use HTTP 400 for either invalid credentials or review-state validation.

Choice: Classify a 400 as authentication only when its message identifies a token or unauthorized failure.

Rationale: Users receive actionable remote validation messages instead of misleading authentication errors.

Deviations

None — implementation followed the approved issue scope, including the explicit exclusion of request-changes reviews.

Tradeoffs

Tradeoff Review comments share the general PR comment endpoint

Alternatives: Keep comment feedback only under pr comment, or expose it through pr review --comment as well.

Choice: Exposed both commands while sharing the same transport implementation.

Rationale: This preserves the gh pr review mental model without inventing a Gitee review-body API.

Tradeoff Approval JSON contains local result metadata

Alternatives: Return no JSON body, synthesize a full review resource, or return a small stable result.

Choice: Return action, repository, and pull request number.

Rationale: Gitee returns an empty success response, so the smaller contract is accurate and useful without fabricating remote fields.

Open Questions

None — the supported actions and Gitee API limitations are documented and test-backed.
